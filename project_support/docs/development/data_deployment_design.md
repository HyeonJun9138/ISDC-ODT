# 배치된 SDC 노드 기반 데이터 관리 설계

## 확인된 문제와 목표

현재 데이터 화면은 노드 탭의 배치 집합 대신 data_center.py의 고정 저장 노드 12개와 SAT-01~05 생성 프로파일을 사용한다. dashboard 조회가 이 명부를 다시 전달하므로 브라우저에 만들어진 노드가 없어도 데이터가 생긴다. 사용자는 노드 탭에서 만들어 배치한 SDC 위성만 데이터 관리 대상으로 삼는 방향을 확인했다.

화면 필터로 예제를 숨기는 대신 데이터 생성 입력을 교체한다. 고정 예제는 회귀시험용 입력으로만 유지하고 기본 운용에서는 사용하지 않는다. 지상 데이터센터, 게이트웨이 캐시와 CelesTrak 위성은 자동으로 등록하지 않는다.

## 대상과 화면 동작

노드 탭에서 배치 버튼으로 반영한 집합만 사용한다. 편집 중인 초안은 포함하지 않는다. 초안 삭제만으로 이미 배치된 집합이 바뀌지 않으며 삭제한 초안을 다시 배치하거나 배치를 해제할 때 반영된다.

배치 집합이 비어 있으면 저장 노드, 카탈로그, 생성량, 작업과 현재 구성의 이벤트가 모두 비어 있어야 한다. 안정성은 100점 대신 평가 대기이며 운영 조치와 스냅샷 전송을 비활성화한다. 네트워크 오류는 빈 배치와 구분하여 동기화 실패로 표시한다.

등록된 SDC 노드의 ID와 이름을 그대로 표시한다. 저장 용량은 노드의 저장 장치 설정을 따르며 기존 고정 512 GB를 임의로 붙이지 않는다. 저장 장치가 없는 배치 노드는 저장소 미설정으로 표시하고 데이터 저장과 복제 대상으로 사용하지 않는다. 활성 DTN 저장 장치의 용량을 합산하며 임의 지상 저장소로 대체하지 않는다.

SIM 텔레메트리는 저장 가능한 배치 노드를 기준으로 기존 30초 생성 간격을 사용한다. 관측 영상은 활성 카메라가 있는 노드만 기존 90초 생성 간격과 400~1200 MB 대표 범위를 적용한다. 과학 관측과 임무 로그는 대응 모델이 없으면 자동 생성하지 않는다. 이 대표 생성 조건은 실측이 아니라 모델 기반 SIM임을 표시한다. 신규 배치 이전 시간의 제품을 소급 생성하지 않는다.

현재 DC-SEOUL을 원본으로 등록하는 DT 운용 스냅샷은 SDC 데이터와 섞지 않는다. 이번 SDC 전용 화면에서는 자동 등록을 끄고 수동 버튼은 지원하지 않는 이유와 함께 비활성화한다. 향후 DT 자체 기록을 다룰 때 별도 출처와 보관 정책으로 설계한다.

## 역할 분리

브라우저 constellation의 deployed는 사용자 배치 입력이다. 배치 명령을 서버에 전달하고, 서버 runtime이 수락한 데이터 운용 구성 사본을 현재 실행의 기준으로 소유한다. 데이터 탭을 조회할 때마다 브라우저 입력으로 서버 상태를 덮어쓰지 않는다.

digital_twin의 모델과 simulation은 구성으로부터 저장 명부와 생성 프로파일을 계산한다. communication은 배치 입력 검증과 ICD 메시지 전달을 맡는다. operations_software/data_management는 전달받은 명부와 제품으로 저장, 복제와 정합성을 처리한다. UI가 정책을 판정하거나 운용 SW가 브라우저 저장소를 읽는 구조는 만들지 않는다.

## 배치 동기화와 구성 변경

서버에 배치 명령과 현재 수락 구성 조회 경로를 추가한다. 요청에는 배치 식별자, 예상 서버 구성 버전과 최대 240개의 노드 명세를 담는다. ID 중복, 잘못된 용량과 장비 형식은 거부한다. 같은 구성의 재전송은 멱등 처리하고 다른 버전에서 수정하면 충돌을 반환한다.

노드의 배치와 배치 해제는 서버 수락 결과를 확인한 후 성공으로 표시한다. 실패 시 사용자의 초안을 보존하고 재시도할 수 있게 한다. 기존 localStorage에 배치가 남아 있는 첫 접속은 서버에 수락된 구성이 없을 때만 복원한다. 다른 브라우저의 수락 구성이 이미 있으면 자동으로 덮어쓰지 않고 현재 서버 구성과 동기화 필요 상태를 표시한다.

데이터 운용 범위는 run_id와 배치 식별자로 구분한다. 구성 변경 후 이전 구성의 객체와 작업을 현재 목록에 섞지 않는다. 브라우저의 선택 객체, 검색에 종속된 선택 노드, 이벤트 커서와 추세도 범위 변경 시 초기화한다. 동일한 구성 재조회나 화면 새로고침만으로 초기화하지 않는다.

기존 예제 데이터와 이전 구성의 모의 데이터는 새 범위에서 보이지 않게 한다. 외부 데이터 관리 모듈의 공유 카탈로그를 삭제하는 요청은 보내지 않는다. 외부 모듈은 범위가 분리된 ICD 확장 계약을 지원해야 하며 미지원이면 호환 불가를 표시하고 동기화를 중단한다. 내장 SIM으로 몰래 대체하거나 예제 데이터를 다시 주입하지 않는다.

구성 범위 선택은 운용 SW의 실제 동작으로 구현하고 빈 인터페이스만 추가하지 않는다. 사용 중인 범위의 노드, 카탈로그, 작업과 이벤트가 함께 바뀌도록 하나의 잠금 아래 적용한다. 동기화가 완료되기 전 도착한 이전 범위의 조회와 조치 결과는 화면을 덮어쓰지 못하게 한다.

## 빈 상태와 복제 판정

명부가 없거나 저장 가능한 노드가 없으면 새 제품과 자동 서비스 요청을 만들지 않는다. 가용성, 복제율과 용량 지표의 분모가 0이면 미평가로 보고한다. 등록된 저장소가 있지만 아직 제품이 없는 상태도 복제 및 정합성을 100% 검증으로 표시하지 않는다.

기존 복제 목표는 유지한다. 저장소 수가 목표보다 적으면 부족 상태를 보여주며 목표를 조용히 낮추거나 존재하지 않는 노드에 복제하지 않는다. 저장 장애와 배치 해제는 구분한다. 장애는 같은 구성의 가용성 변화이고 배치 해제는 빈 구성으로의 전환이다.

## 검증

먼저 노드를 배치하지 않은 기본 앱에서 dashboard가 고정 예제 12개와 제품을 반환하는 현상을 회귀시험으로 재현한다. 이후 빈 배치, 초안만 존재, 실제 배치, 저장 장치 없음, 카메라 유무, 중복 동기화, 배치 해제, 재배치, 실행 초기화와 예제 데이터 혼입 방지를 검증한다.

API 시험은 입력 검증, 버전 충돌, 서버 인스턴스 격리, 사본 소유권, 동기화 실패와 외부 모듈의 범위 계약 미지원 처리를 다룬다. 기존 데이터 모듈의 저장과 복제 계산 회귀시험은 명시적 시험 명부로 유지한다. 브라우저 시험은 빈 상태 문구, 평가 대기, 조치 비활성화와 늦은 응답 배제를 검사한다.

완료 전 전체 python -m pytest -q와 Node 브라우저 시험을 실행하고 별도 검증 서버에서 노드 생성, 배치, 데이터 생성 및 배치 해제를 확인한다. 사용자 운용 서버의 실제 카탈로그나 외부 데이터를 지우지 않는다.
