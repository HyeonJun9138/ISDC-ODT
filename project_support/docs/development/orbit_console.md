# 궤도 탭 사용 및 계산 규칙

## 화면 사용

지도 제어는 대시보드, 노드, 통신 지도에 공통으로 적용한다. 오른쪽 아래 조준 버튼과 세로 확대 슬라이더는 어두운 테마에서 지도 도구 모음과 같은 남색을 사용하고, 밝은 테마에서는 옅은 청회색으로 표시한다. 상단의 해 음영 버튼을 바꾸면 세 지도에 같은 설정이 적용되며, 나중에 연 지도와 새로고침한 화면도 저장된 설정을 따른다.

대시보드의 `뷰 정렬`은 지구 화면 오른쪽 아래에 있는 조준 아이콘 버튼이다. 선택 위성을 가까이에서 추적하는 기존 동작을 유지하며, 위성을 선택하지 않았거나 위치를 계산할 수 없으면 비활성화된다. 그 아래의 +/− 버튼과 세로 슬라이더로 확대 수준을 조절한다. 슬라이더를 위로 올리면 확대하고 아래로 내리면 축소한다. 마우스 휠이나 뷰 초기화로 시점이 바뀌면 슬라이더 표시도 갱신된다. Cesium을 사용할 수 없는 대체 좌표도에서는 확대 제어를 비활성화한다.

확대 버튼은 카메라의 휠 동작을 재사용한다. 슬라이더는 현재 카메라를 담당하는 지구 뷰 또는 위성 추적 뷰에 목표 거리를 전달하며, 카메라 애니메이션을 따라 표시가 갱신된다. 2D의 목표 거리는 직교 투영의 수평 표시 폭이다. 이 UI 변경은 서버 API나 궤도 계산식을 바꾸지 않는다.

왼쪽 카탈로그에서 위성명, NORAD 또는 COSPAR로 검색한다. 열 제목을 누르면 오름차순과 내림차순이 바뀐다. 빈 값은 항상 마지막에 배치한다. 목록은 32 px 높이의 가상 행으로 표시하며, 수만 개의 객체를 DOM에 동시에 만들지 않는다. 검색과 궤도군, 관심 위성 필터는 지도에도 적용한다. 현재 선택한 위성은 필터 밖에 있더라도 분석을 계속할 수 있도록 지도에 남긴다.

한 번 클릭하면 선택이 바뀌고 현재 거리를 유지한 채 그 위성이 화면 중앙의 하향 시점으로 온다. 두 번 클릭하거나 `뷰 정렬`, 목록의 Enter 키를 사용하면 해당 위성으로 다가가 분석 시각에 따른 위치를 계속 따라간다. `뷰 초기화`는 추적을 풀고 지구 전체 보기로 돌아간다. 3D에서는 위성 모델 중심의 근접 시점이고, 2D에서는 북쪽을 위로 고정한 지도에서 위성의 경위도를 중심으로 본다. 화살표, Home, End와 PageUp/PageDown 키로 목록을 탐색한다. 오른쪽 별표로 관심 위성을 등록한다. 관심 목록은 해당 브라우저의 localStorage에만 저장된다. 저장을 사용할 수 없는 환경에서는 현재 세션에서만 유지된다.

2D에서 휠을 위로 굴리면 선택 위성의 지도상 위치를 중심으로 확대한다. 3D 카메라 거리 대신 직교 투영의 수평 표시 폭을 조절하며, 최소 폭은 1 km다. `뷰 정렬`의 초기 폭은 500 km이며 지도 문맥을 유지하기 위한 화면 설정이지 센서 관측 폭이 아니다. 추적 중 휠 축소로 폭이 20,000 km 이상이 되거나 Esc, 뷰 초기화 버튼 또는 3D/2D 전환을 누르면 추적을 해제한다. 지도에서 직접 드래그를 시작해도 추적을 풀고 현재 위치에서 자유롭게 이동한다. 2D 전환 도중의 휠 입력은 무시하고 완료 후 북쪽 위 방향을 복원한다. 2D 지도에서는 지구 뒤편 가림 조건을 적용하지 않는다.

### 카메라 이동 규칙

휠과 확대 버튼은 최종 거리를 예약하고 렌더링 프레임마다 현재 거리에서 이어서 이동한다. 반대 방향 입력은 아직 도착하지 않은 목표를 버리고 실제 보이는 위치에서 방향을 바꾼다. 멀리 있는 선택 모델에는 더 큰 거리 비율을 적용하며, 근접 구간에 들어오면 모델 대표 치수의 약 세 배 거리로 접근한다. 작은 CubeSat에는 기존 20 m 최소 포커스 거리를 강제하지 않는다. 그 대신 모델별 최소 접근 거리의 1.5배 여유를 확보한다. 모델 배율, 점 크기, 테두리와 불투명도는 이 카메라 조정에서 바꾸지 않는다.

위성 선택과 뷰 정렬은 위치뿐 아니라 전체 자세를 함께 보간한다. 반대쪽에서 보던 자세도 중간에 화면이 뒤집히지 않도록 quaternion 보간을 사용한다. 지구 뒤편의 표적은 우선 넓은 지구 조망으로 이동한 뒤 현재 위치를 다시 확인하고 추적을 시작한다. 도착할 때도 가려져 있거나 위치가 없으면 오래된 위치로 재비행을 반복하지 않는다. 모델 로딩 중 예약한 포커스도 새 드래그나 선택 해제로 취소된다.

구현은 `digital_twin/visualization/camera_motion.js`의 거리 및 자세 보간을 지구 카메라와 위성 추적 카메라가 공유한다. 시간 기준은 `performance.now()`이며 분석 시계가 정지하거나 배속이 달라져도 조작 속도는 변하지 않는다. 프레임 지연은 한 번에 최대 50 ms만 반영하므로 숨겨진 화면의 이동을 복귀 순간에 몰아서 실행하지 않는다. 기본 거리 보간 시정수는 180 ms다. 2D/3D 전환은 1.5초이며, 전환 중 마우스 입력으로 애니메이션 끝으로 건너뛰지 않는다. 지구 회전과 평면 이동에는 Cesium의 기본 드래그 처리와 감쇠를 유지한다.

다른 화면을 연결할 때는 `zoomBy(delta)` 또는 `setZoomDistance(meters)`를 호출한다. 호출 직후 카메라 위치가 바뀐다고 가정하지 말고 `zoomDistance()`나 렌더링 완료 시점의 실제 값을 읽는다. 일반 지구 이동은 `GlobeController.flyTo()`를 통해 기존 줌과 추적을 해제하며, 직접 입력은 `SatelliteModelLayer.interruptCamera()`로 넘긴다. 3D에서는 추적 프레임 안의 회전을 허용하고 2D에서는 중심 추적을 해제한다. 원시 `camera.flyTo()`와 추적 갱신을 같은 프레임에서 경쟁시키지 않는다.

Cesium의 [카메라 비행 계약](https://cesium.com/learn/cesiumjs/ref-doc/Camera.html), [드래그 감쇠 및 프레임별 이동 제한](https://cesium.com/learn/cesiumjs/ref-doc/ScreenSpaceCameraController.html), [모드 전환의 입력 처리](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html)를 기준으로 연결했다. 이는 화면 조작 개선이며 GP 전파, SIM 상태나 실제 위성 자세 계산의 변경이 아니다.

오른쪽은 전파 위치, 평균 궤도요소, SATCAT 식별 정보, 데이터 이력을 구분한다. 위성 장비의 건강도나 전력, 온도는 GP에서 알 수 없으므로 궤도 탭에 표시하지 않는다. SATCAT 운용 상태는 목록 제공자의 코드이며 현재 장비를 측정한 판정이 아니다. 누락된 수치는 `미제공` 또는 `—`로 표시한다.

하단의 시계는 UTC 분석 커서다. 현재 시각, 정지, 60초 스텝, 배속, UTC 직접 입력을 제공한다. 서버의 SIM 시계, 시나리오와 다른 탭의 런타임을 변경하지 않는다. 관측창 표의 AOS 또는 타임라인 구간을 누르면 해당 시각으로 이동해 정지한다. 표의 기준 시각을 확인하고 필요하면 `재계산`한다. 진행 중에는 분석 커서가 기준 시각에서 5분 이상 벗어날 때 재계산하며 계산 간격은 벽시계 기준 최소 5초다.

## 데이터의 실제성

### GP와 SGP4

CelesTrak GP/OMM 평균 요소를 satellite.js 7.0.1의 SGP4로 전파한다. 위치 표시는 WGS84 지리 위도와 경도, 타원체 고도다. 표시 속력은 SGP4의 TEME 속도벡터 크기이며 지상 속력이 아니다. GP는 실측 텔레메트리가 아니고 현재 하드웨어 상태를 제공하지 않는다. 근지점과 원지점, 주기와 장반경은 기존 평균 운동 기반 근사 요약값이다.

GP에서 시간대가 생략된 Epoch는 UTC로 읽는다. 목록의 Δt는 **현재 벽시계 UTC − Epoch**, 오른쪽의 `분석시각 − Epoch`는 분석 커서 기준 차이다. 음수는 Epoch보다 과거를 분석한다는 뜻이다. 절대 시간 차이가 120시간을 넘으면 주의를 표시하지만, 이 문턱은 오차 보증이나 운영 적합성 판정이 아니다. 객체별 궤도 오차, 공분산 및 기동 정보는 제공하지 않는다.

실제 GP의 파싱 또는 전파가 실패하면 그 위치와 라벨을 숨긴다. 이전 정상 위치를 고정한 채 최신 값처럼 표시하지 않고, 합성 궤도로 대체하지도 않는다. Cesium만 사용할 수 없으면 동일한 계산값을 2D 경위도 좌표도에 표시한다. satellite.js도 없으면 실제 GP 위치는 미제공이다. 이 좌표도는 지도 영상이나 실제 위성 촬영 화면이 아니다.

### 명시적 DEMO

`demo === true`인 자산만 모의 계산을 수행한다. 고도와 궤도 경사각, 초기 위상이 명시적으로 제공되어야 한다. 원형 2체 모델의 각속도는 `sqrt(mu / r^3)`, 속력은 `sqrt(mu / r)`다. 지구 자전과 경사 궤도면 회전을 반영하여 WGS84 지리 좌표로 변환한다. `mu = 398600.4418 km^3/s^2`, 적도 반경은 6378.137 km다.

DEMO의 `altitude_km`는 궤도 반경에서 지구 적도 반경을 뺀 값이다. 따라서 표시되는 WGS84 타원체 고도는 위도에 따라 조금 달라질 수 있다. 위상은 Unix epoch에 가상 관성 승교점 축과 그리니치를 일치시킨 기준이다. 실제 위성의 관측 자료에 맞춘 궤도가 아니다. 섭동, 대기 저항, 기동과 이심 궤도는 이 DEMO에 포함하지 않는다. 실제 NORAD와 참조 번호가 같아도 SATCAT의 실제 메타데이터를 섞지 않는다.

### 지상 관측

서울, 제주, 스발바르, 알래스카와 아타카마의 좌표는 **관측 기준점**이다. 연결된 실제 안테나나 장비를 의미하지 않는다. 지점 고도는 모두 WGS84 0 km를 가정한다. 지형 고도와 장비 정보가 추가되면 모델 정의와 검증을 함께 바꾼다.

WGS84 ECEF에서 관측점의 ENU 좌표계로 변환해 방위각, 고각 및 경사거리를 계산한다. 방위각은 북쪽 0°, 동쪽 90°다. 천정과 천저에서는 방위각이 유일하지 않아 0° 관례를 사용한다. 고각이 선택한 마스크 이상인 경우만 기하학적으로 관측 가능하다고 표시한다. 지형, 굴절, 기상, 안테나 추적 제한, 주파수와 링크 예산은 포함하지 않는다.

24시간을 30초 간격으로 표본화하고, 표본으로 포착한 국소 최대를 정밀화한다. 고각 마스크 교차의 시간 구간을 1초 이하로 이분한다. 이는 수치 탐색의 정밀도이지 실제 AOS/LOS 오차가 1초라는 뜻이 아니다. 극히 짧아 표본에서 포착하지 못한 패스나 결측 구간은 보장할 수 없다.

`진행 중*`은 검색 시작 전에 이미 마스크 위에 있던 구간이다. `부분 구간*`은 검색 끝이나 전파 결측으로 경계가 확인되지 않은 구간이다. 이때 표시한 지속 시간은 확인된 부분만의 길이다. 전파 결측이 있으면 완전한 24시간 예측으로 주장하지 않는다. 계산 가능한 관측창이 없는 경우와, 결측으로 여부를 판정할 수 없는 경우를 구분한다.

## 코드 확장 규칙

- 물리 전파와 관측 기하는 `digital_twin/simulation/browser/orbit.js`에 둔다. DOM, API와 저장소를 호출하지 않는다.
- Cesium/Canvas 표현과 가시성은 `digital_twin/visualization/globe.js`가 담당한다. 서버 SIM 상태를 변경하지 않는다.
- 목록의 순수 필터와 형식 정책은 `scripts/orbit/catalog.js`, 가상 목록은 `catalog_view.js`, 화면 분석 커서는 `clock.js`, 상세 정보는 `inspector.js`에 둔다.
- `scripts/tabs/orbit.js`는 조회와 화면 이벤트를 조립한다. 카탈로그와 SATCAT 응답의 경합을 막고 실패 시 이전 출처를 새 출처로 위장하지 않는다.
- 궤도 스타일은 `styles/orbit.css`에 한정하고 `#view-orbit` 또는 활성 궤도 화면 조건으로 범위를 제한한다.
- 새로운 수치는 근거, 단위, 좌표계, 시간 기준과 결측 정책을 먼저 정의한다. 불명 값을 0, 정상, 100%로 보완하지 않는다.
