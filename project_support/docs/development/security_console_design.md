# 보안 모니터링 화면 설계

작성일: 2026-09-08

## 목적과 승인 범위

사용자가 승인한 SIM 기반 보안 모니터링 화면을 기존 웹 콘솔에 추가한다. 데이터 송수신의 모의 상태와 실제 브라우저 연결 상태를 구분해서 보여준다. 이 작업은 암호화나 인증 기능을 새로 구현하는 작업이 아니다.

상단 탭 순서는 대시보드, 노드, 통신, 데이터, 보안, 임무, 상태, 설정으로 한다. 기존 데이터 관리 탭의 표시 이름만 데이터로 바꾸고 내부 식별자와 API는 유지한다. 버튼의 좌우 여백과 구분 간격을 줄이되 키보드 포커스와 읽기 쉬운 높이는 유지한다. 좁은 화면에서는 제목이나 실행 정보와 겹치지 않도록 탐색 영역을 스크롤할 수 있게 한다.

## 화면 구성

상단에는 SIM 모니터링임을 명시한 설명과 마지막 수신 시각, 스트림 상태를 배치한다. 실제 보안 검증이 아니라는 안내는 접거나 숨기지 않는다.

중앙에는 위성, 중계, 지상국으로 이어지는 송수신 개념도를 둔다. 실제 선택된 위성의 통신 경로라고 표현하지 않는다. 송신과 수신 방향에 움직이는 패킷을 표시하고 각 구간에 방패 모양 상태 마크와 텍스트를 함께 배치한다. 패킷 움직임은 모의 흐름의 시각화이며 실제 패킷 캡처나 구간별 측정값이 아니다. 방패는 보안 관측 지점을 뜻하며 검증 완료를 뜻하는 체크 마크는 사용하지 않는다.

지표 영역에는 기존 SIM 인증률, SIM 처리량과 패킷 손실률을 표시한다. 실제 파일 무결성은 검증 입력 없음으로 표시한다. 인증률을 무결성 검증률로 바꾸어 부르거나 링크 품질만으로 보안 정상 여부를 판정하지 않는다. 인증률이 99% 미만이면 기존 SIM KPI 기준에 따른 경고를 표시한다. 결측값이나 비정상 숫자는 0 또는 정상으로 대체하지 않는다.

별도 연결 상태 영역에는 현재 페이지의 HTTP 또는 HTTPS, 텔레메트리의 WS 또는 WSS와 연결 상태를 표시한다. 이는 브라우저와 웹 서버 사이 구간만 설명한다. HTTPS/WSS에서도 위성 구간 암호화나 사용자 인증이 검증됐다고 표현하지 않는다. 현재 앱의 서버 인증 미구현 안내는 항상 표시한다.

기술 영역에는 CCSDS SDLS, PQC, TEE / Mesh-PUF, OTAR 및 제로트러스트를 배치한다. 실제 구현이 없는 항목은 미연동으로 표시한다. 기존 PQC-TEE 장비 정보가 있으면 MOCK 장비라는 출처와 연결 여부를 별도로 보여주며 실제 하드웨어 신뢰 검증이나 mTLS 세션 증명으로 사용하지 않는다. 키 교체 버튼이나 보안 활성화 버튼처럼 구현되지 않은 조작은 만들지 않는다.

하단에는 이 화면에서 관측한 스트림 연결 변경과 SIM 인증 경고 전환을 최대 40건까지 표시한다. 이를 보안 감사 로그 또는 공격 탐지 결과라고 부르지 않는다. 최초 수신은 기준 상태로 기록하고 이후 상태가 달라질 때만 추가한다. 현재 브라우저 세션의 이력이며 새로고침하면 초기화된다고 안내한다.

## 상태와 데이터 흐름

기존 app.js가 받는 텔레메트리 사본과 연결 상태를 보안 탭에 전달한다. 새로운 서버 API, 전역 상태 저장소, 보안 엔진 또는 내부 이벤트 버스를 추가하지 않는다. 기존 SIM 계산식과 응답 형식은 변경하지 않는다.

보안 탭은 마지막 텔레메트리 수신 시각, 최대 40건의 화면 관측 이력과 화면 렌더링 정보만 보유한다. 서버나 기존 store의 데이터를 수정하지 않는다. 수신 전에는 대기, 마지막 수신 후 10초가 지나면 지연, 연결이 닫히거나 오류가 나면 연결 끊김으로 표시한다. 지연과 단절 시 이전 값에는 마지막 수신값임을 표시하고 흐름 애니메이션을 중지한다.

SIM이 일시정지되거나 처리량이 0 또는 결측이면 모의 패킷 애니메이션을 중지한다. 보안 탭을 벗어나거나 브라우저 페이지가 숨겨져 있을 때도 애니메이션을 중지한다. 탭에 돌아오면 다음 메시지를 기다리지 않고 현재 사본으로 즉시 화면을 갱신한다. 시스템의 모션 감소 설정에서는 정적인 방향 표시로 대체한다.

새 실행 식별자가 수신되면 이전 실행의 지표와 관측 이력이 섞이지 않도록 화면 이력을 초기화한다. 시각은 브라우저 수신 시각과 SIM 경과 시각을 구분한다. 실제 송신 시각이나 종단 지연은 추정하지 않는다.

## 구현 위치

- user_application/web/index.html: 여덟 번째 탭과 보안 화면의 의미 있는 HTML 구조.
- user_application/web/scripts/app.js: 보안 화면 초기화, 텔레메트리와 연결 상태 전달, 탭 변경 시 갱신.
- user_application/web/scripts/tabs/security.js: 화면 조립과 생명주기.
- user_application/web/scripts/security/view_model.js: 입력 사본에서 표시값과 경고를 도출하는 순수 함수.
- user_application/web/styles/security.css: 보안 화면 전용 스타일과 SVG/CSS 흐름 애니메이션.
- 기존 탐색 스타일: 상단 버튼의 밀도와 작은 화면 대응만 제한적으로 수정.

개념도는 HTML/SVG/CSS로 구현하며 새 이미지, 3D 지구, 라이브러리 또는 독립 렌더링 루프를 추가하지 않는다. 다크 모드와 라이트 모드의 기존 색상 변수를 사용한다.

## 검증과 완료 조건

코드 변경 전에 관련 회귀시험을 추가하고 실패를 확인한다. 순수 표시 함수 시험은 정상 입력, 결측, 숫자 범위, 99% 경계, 오래된 수신, 연결 단절, 정지 상태, HTTPS와 보안 검증의 구분을 다룬다. 관측 이력은 중복 방지와 40건 제한, 실행 변경 초기화를 검증한다.

웹 자산 시험은 여덟 개 탭의 순서, 데이터 표시 이름, 보안 화면과 로컬 모듈 제공 여부를 검증한다. 기존 탭과 API 계약을 보존한다. 전체 python -m pytest -q와 Node 브라우저 단위시험을 실행한다.

별도 브라우저 세션에서 다크 및 라이트 모드, 1280x720 화면, 탭 복귀, 수신 단절, SIM 정지, 모션 감소 설정을 확인한다. 미연동 기술이 정상 보안으로 보이거나 연결이 끊겨도 움직이는 상태를 완료로 인정하지 않는다. 검증 결과와 남은 한계는 CURRENT.md에 기록한다.

## 제외 범위

실제 SDLS 프레임 처리, PQC 암호 연산, TEE/PUF 검증, OTAR 키 배포, 사용자 인증, 침입 탐지, 패킷 수집과 영구 감사 로그는 포함하지 않는다. 실제 장비나 보안 서비스의 입력 계약이 마련되면 별도 작업으로 설계한다.
