# 보안 모니터링 화면 설계

작성일: 2026-09-08

개정: 보안 운용 SW의 독립 로직과 설정 화면의 외부 시스템 표현을 추가한다. 사용자 승인 후 구현했으며 현재 동작과 검증 기록은 security_console.md와 CURRENT.md에 있다.

## 목적과 승인 범위

사용자가 승인한 SIM 기반 보안 모니터링 화면을 기존 웹 콘솔에 추가한다. 보안은 화면 내부 기능이 아니라 별도 운용 SW 모듈로 구현한다. 데이터 송수신의 모의 상태와 실제 브라우저 연결 상태를 구분해서 보여준다. 이 작업은 암호화나 인증 기능을 새로 구현하는 작업이 아니다.

## 모듈 분리와 선택한 구조

UI에서 보안 규칙을 계산하는 방식은 책임이 섞이므로 사용하지 않는다. 처음부터 외부 보안 제품을 전제로 하는 방식도 실제 제품의 프로토콜과 장비가 없어 이번 범위에 맞지 않는다. 기존 데이터 관리와 데이터 패브릭처럼 메시지 계약을 가진 내장 stand-in을 구현하고, 같은 계약을 제공하는 별도 프로세스로 교체할 수 있는 방식을 선택한다.

DT는 현재 SIM 상태와 관측값을 소유한다. 기존 인증률, 처리량과 손실률을 사본으로 제공하며 보안 정책을 판정하지 않는다. 별도 보안 운용 SW는 전달받은 관측값으로 규칙을 평가하고 자기 모듈의 판정, 입력 순서와 이벤트 이력을 소유한다. DT의 현재 상태를 수정하거나 다른 운용 SW를 직접 호출하지 않는다.

통신 계층은 입력과 응답 스키마, 시간 제한, 오류 변환과 메시지 전달만 맡는다. 조립 지점인 user_application이 내장 보안 모듈 또는 외부 HTTP 어댑터를 주입한다. digital_twin과 operations_software 사이에는 직접 import를 만들지 않는다. 기존 데이터 관리 및 데이터 패브릭의 공개 API와 계산식은 바꾸지 않는다.

화면은 모듈의 판정과 출처를 표시하고 브라우저 연결의 수신 지연만 별도로 계산한다. 인증 임계값을 브라우저와 서버에 중복 구현하지 않는다. 별도 모듈이라는 말은 반드시 별도 프로세스에서 실행 중이라는 뜻이 아니며 내장 또는 외부 배치를 명시한다.

## 설정 화면의 모듈과 외부 시스템

운용 SW 모듈 영역에 보안 운용 SW를 추가한다. 이 카드에는 배치 방식, 모듈 응답 상태, 계약 버전과 SIM 규칙 판정이라는 구현 범위를 표시한다. 기존 세 개 카드와 검증 지원 영역을 재배치해 카드나 연결선이 겹치지 않게 한다.

외부 시스템 영역에는 외부 보안 시스템 카드를 별도로 추가한다. 이는 PQC/TEE 장비, SDLS 종단과 키 관리 시스템을 연계할 대상의 표현이다. 실제 제품이나 종단 주소가 지정되지 않았으므로 기본값은 미연동이며 자동 네트워크 접속을 시도하지 않는다. 기존 PQC-TEE MOCK 장비를 실제 외부 시스템의 연결 증거로 사용하지 않는다.

DT와 보안 운용 SW 사이에는 ICD-08 보안 모니터링 연동을 초안으로 등록한다. 외부 보안 시스템 연결은 별도 링크로 표현하고 기본 비활성 상태로 둔다. 설정의 연결 확인을 실행하더라도 TCP 접속 성공은 도달 가능으로만 표시하며 보안 프로토콜 검증 완료로 바꾸지 않는다. UDP 주소 해석 역시 응답 확인으로 표현하지 않는다.

외부 보안 운용 SW 배포 주소는 서버 설정 SPACETWIN_SECURITY_URL로 지정하고 재시작 후 반영한다. 주소가 없으면 내장 모듈을 사용한다. 설정 화면에는 서버가 보고한 실제 배치와 주소를 보여준다. 기존 브라우저의 링크 진단용 주소 변경과 실제 모듈 교체 설정은 구분하며 진단 설정 저장만으로 외부 모듈로 전환됐다고 표시하지 않는다. 외부 보안 장비의 실제 프로토콜 어댑터는 이번 범위에 포함하지 않는다.

## 보안 모듈의 실제 수행 로직과 메시지 계약

operations_software/security에 SecurityStandIn을 구현한다. 빈 모듈 대신 인증률의 유효 범위와 99% 기준 판정, 관측 누락 표시, 실행별 상태 전환 및 중복 이벤트 방지를 실제로 수행한다. 정책은 조립 지점에서 전달하는 운용 설정으로 두며 임의 공격 이벤트나 새 난수를 생성하지 않는다. 손실률과 처리량은 전달 상태의 참고값이지 인증 성공의 근거가 아니다. 암호화와 실제 파일 무결성은 증거 없음으로 남긴다.

계약은 observe(message), overview(), events(after), status()로 제한한다. observe 입력에는 계약 버전, run_id, sample_id, SIM 경과 초, 관측 생성 UTC 시각, source=SIM, 인증률과 처리량 및 손실률을 포함한다. SIM 실행 정지 여부와 장비 정보는 출처를 유지한 부가 정보로 전달한다. 브라우저의 WS 연결 상태는 이 모듈의 보안 입력으로 섞지 않는다.

모듈은 새 실행이 시작되면 입력 순서와 이력을 초기화한다. sample_id가 같거나 같은 실행에서 이전 시각의 관측이 도착하면 판정을 덮어쓰거나 이벤트를 추가하지 않는다. SIM이 정지한 동안 같은 스냅샷을 조회해도 이벤트가 늘어나지 않는다. 입력 사본을 보관하고 반환값도 사본으로 제공하며 잠금으로 동시 접근을 보호한다. 이력은 최대 200건의 메모리 기록이며 UI는 최근 40건을 표시한다. 영구 보안 감사 기록이 아니다.

응답은 입력 출처, 계약 버전, 판정 근거, 모듈 구현 방식, 실행 식별자와 마지막 관측 시각을 포함한다. SIM 인증률이 정상이어도 전체 보안 정상이라는 종합 판정은 만들지 않는다. 결측이나 유효 범위 밖의 값은 미확인이고 인증률을 0으로 대체하지 않는다.

모듈 측 HTTP 경로는 POST /api/security/observations, GET /api/security/overview, GET /api/security/events와 GET /api/security/status로 한다. 콘솔 측 GET /api/security/dashboard는 현재 DT 스냅샷을 계약 메시지로 전달한 뒤 결과를 모아 반환한다. 모든 브라우저가 같은 run_id와 SIM 경과 시각으로 sample_id를 만들도록 서버에서 처리해 다중 조회 중복을 방지한다. 버전과 필드 형식은 HTTP 스키마에서 검증한다.

외부 어댑터는 같은 경로를 사용하고 2.5초 시간 제한을 적용한다. 외부 응답의 계약 버전과 필수 필드를 검증하며 잘못된 응답, 시간 초과와 접속 실패는 미연동 또는 오류로 표시한다. 외부 모듈이 실패했을 때 내장 SIM으로 몰래 대체하지 않는다. 자동 재시도 루프를 추가하지 않고 다음 화면 조회에서 다시 확인한다. 클라이언트와 자원은 앱 종료 시 정리하며 import 또는 객체 생성만으로 네트워크나 시계를 시작하지 않는다.

상단 탭 순서는 대시보드, 노드, 통신, 데이터, 보안, 임무, 상태, 설정으로 한다. 기존 데이터 관리 탭의 표시 이름만 데이터로 바꾸고 내부 식별자와 API는 유지한다. 버튼의 좌우 여백과 구분 간격을 줄이되 키보드 포커스와 읽기 쉬운 높이는 유지한다. 좁은 화면에서는 제목이나 실행 정보와 겹치지 않도록 탐색 영역을 스크롤할 수 있게 한다.

## 화면 구성

상단에는 SIM 모니터링임을 명시한 설명과 마지막 수신 시각, 스트림 상태를 배치한다. 실제 보안 검증이 아니라는 안내는 접거나 숨기지 않는다.

중앙에는 위성, 중계, 지상국으로 이어지는 송수신 개념도를 둔다. 실제 선택된 위성의 통신 경로라고 표현하지 않는다. 송신과 수신 방향에 움직이는 패킷을 표시하고 각 구간에 방패 모양 상태 마크와 텍스트를 함께 배치한다. 패킷 움직임은 모의 흐름의 시각화이며 실제 패킷 캡처나 구간별 측정값이 아니다. 방패는 보안 관측 지점을 뜻하며 검증 완료를 뜻하는 체크 마크는 사용하지 않는다.

지표 영역에는 기존 SIM 인증률, SIM 처리량과 패킷 손실률을 표시한다. 실제 파일 무결성은 검증 입력 없음으로 표시한다. 인증률을 무결성 검증률로 바꾸어 부르거나 링크 품질만으로 보안 정상 여부를 판정하지 않는다. 인증률이 99% 미만이면 기존 SIM KPI 기준에 따른 경고를 표시한다. 결측값이나 비정상 숫자는 0 또는 정상으로 대체하지 않는다.

별도 연결 상태 영역에는 현재 페이지의 HTTP 또는 HTTPS, 텔레메트리의 WS 또는 WSS와 연결 상태를 표시한다. 이는 브라우저와 웹 서버 사이 구간만 설명한다. HTTPS/WSS에서도 위성 구간 암호화나 사용자 인증이 검증됐다고 표현하지 않는다. 현재 앱의 서버 인증 미구현 안내는 항상 표시한다.

기술 영역에는 CCSDS SDLS, PQC, TEE / Mesh-PUF, OTAR 및 제로트러스트를 배치한다. 실제 구현이 없는 항목은 미연동으로 표시한다. 기존 PQC-TEE 장비 정보가 있으면 MOCK 장비라는 출처와 연결 여부를 별도로 보여주며 실제 하드웨어 신뢰 검증이나 mTLS 세션 증명으로 사용하지 않는다. 키 교체 버튼이나 보안 활성화 버튼처럼 구현되지 않은 조작은 만들지 않는다.

하단에는 보안 모듈이 보고한 SIM 판정 전환을 최근 40건까지 표시한다. 이를 보안 감사 로그 또는 공격 탐지 결과라고 부르지 않는다. 최초 수신은 기준 상태로 기록하고 이후 상태가 달라질 때만 추가한다. 모듈 실행 중의 메모리 이력으로, 브라우저 새로고침과 모듈 재시작을 구분한다. 브라우저 연결 변경은 별도 연결 상태 영역에서 표시한다.

## 상태와 데이터 흐름

보안 화면은 /api/security/dashboard에서 모듈 보고를 조회하고 기존 app.js에서 브라우저 연결 상태를 전달받는다. 보안 탭이 보이는 동안 2초 간격으로 이전 조회가 끝난 뒤 다음 조회를 예약하며 중복 요청을 만들지 않는다. 화면 진입 시 즉시 조회하고 이탈 시 예약과 미완료 요청을 정리한다. 별도 서버 주기 작업은 만들지 않는다. 모듈 관측은 콘솔 조회에 의해 수행되므로 숨겨진 동안에도 연속 감사하는 서비스라고 표현하지 않는다. 기존 SIM 계산식과 기존 API 응답 형식은 변경하지 않는다.

보안 탭은 마지막 모듈 보고 수신 시각과 표시용 사본만 보유한다. 서버나 기존 store의 데이터를 수정하지 않는다. 수신 전에는 대기, 마지막 성공 조회 후 10초가 지나면 지연, 조회 실패 시 오류로 표시한다. WebSocket 연결 상태는 이와 별도로 보여주며 모듈 응답과 혼동하지 않는다. 어느 한쪽이라도 지연 또는 단절이면 이전 값에 마지막 수신값임을 표시하고 흐름 애니메이션을 중지한다.

SIM이 일시정지되거나 처리량이 0 또는 결측이면 모의 패킷 애니메이션을 중지한다. 보안 탭을 벗어나거나 브라우저 페이지가 숨겨져 있을 때도 애니메이션을 중지한다. 탭에 돌아오면 다음 메시지를 기다리지 않고 현재 사본으로 즉시 화면을 갱신한다. 시스템의 모션 감소 설정에서는 정적인 방향 표시로 대체한다.

새 실행 식별자가 수신되면 이전 실행의 표시 사본을 비우고 새 모듈 보고를 표시한다. 늦게 도착한 이전 조회 응답으로 새 화면을 덮어쓰지 않는다. 시각은 브라우저 수신 시각, 모듈 관측 시각과 SIM 경과 시각을 구분한다. 실제 송신 시각이나 종단 지연은 추정하지 않는다.

## 구현 위치

- user_application/web/index.html: 여덟 번째 탭과 보안 화면의 의미 있는 HTML 구조.
- user_application/web/scripts/app.js: 보안 화면 초기화, 텔레메트리와 연결 상태 전달, 탭 변경 시 갱신.
- user_application/web/scripts/tabs/security.js: 화면 조립과 생명주기.
- user_application/web/scripts/security/view_model.js: 모듈 판정 사본의 표시값과 UI 수신 지연을 정리하는 순수 함수. 보안 정책을 다시 판정하지 않는다.
- user_application/web/styles/security.css: 보안 화면 전용 스타일과 SVG/CSS 흐름 애니메이션.
- 기존 탐색 스타일: 상단 버튼의 밀도와 작은 화면 대응만 제한적으로 수정.
- operations_software/security: 독립 SIM 보안 판정 로직과 모듈 소유 이력.
- digital_twin/contracts/security.py: 보안 연동 Protocol과 접근 실패 계약.
- communication/http/security.py와 보안 전용 wire schema: DT 스냅샷 전달, API 검증과 응답 조립.
- communication/external/security.py: 외부 보안 운용 SW용 HTTP 어댑터.
- user_application/configs/security.py: SIM 인증 기준과 운용 설정. 모델 정의와 구분한다.
- user_application/web/application.py: 내장 또는 외부 모듈의 조립과 자원 정리.
- user_application/web/scripts/settings/topology.js 및 필요한 설정 렌더링 코드: 보안 모듈, 외부 시스템, 링크와 ICD 초안.

개념도는 HTML/SVG/CSS로 구현하며 새 이미지, 3D 지구, 라이브러리 또는 독립 렌더링 루프를 추가하지 않는다. 다크 모드와 라이트 모드의 기존 색상 변수를 사용한다.

## 검증과 완료 조건

코드 변경 전에 관련 회귀시험을 추가하고 실패를 확인한다. 보안 모듈 시험은 정상 입력, 결측, 숫자 범위, 99% 경계, 중복 및 역순 입력, SIM 정지, 실행 변경과 이력 제한을 다룬다. 순수 표시 함수 시험은 오래된 수신, 연결 단절, 정지 상태, HTTPS와 보안 검증의 구분을 다룬다. 앱 인스턴스 격리, 입력 및 반환 사본, HTTP 스키마 오류와 외부 어댑터 오류를 검증한다. 계층 의존성 시험으로 DT와 운용 SW의 직접 import를 금지한다.

설정 시험은 신규 카드, 링크와 ICD 참조의 일관성, 기존 저장 설정과의 호환성, 외부 시스템의 기본 비활성 상태, 진단과 실제 배치의 구분을 검증한다. 외부 네트워크 대신 HTTP transport 대역을 사용한다. 기존 설정 화면의 레이아웃 시험도 유지한다.

웹 자산 시험은 여덟 개 탭의 순서, 데이터 표시 이름, 보안 화면과 로컬 모듈 제공 여부를 검증한다. 기존 탭과 API 계약을 보존한다. 전체 python -m pytest -q와 Node 브라우저 단위시험을 실행한다.

별도 브라우저 세션에서 다크 및 라이트 모드, 1280x720 화면, 탭 복귀, 수신 단절, SIM 정지, 모션 감소 설정을 확인한다. 미연동 기술이 정상 보안으로 보이거나 연결이 끊겨도 움직이는 상태를 완료로 인정하지 않는다. 검증 결과와 남은 한계는 CURRENT.md에 기록한다.

## 제외 범위

실제 SDLS 프레임 처리, PQC 암호 연산, TEE/PUF 검증, OTAR 키 배포, 사용자 인증, 침입 탐지, 패킷 수집과 영구 감사 로그는 포함하지 않는다. 실제 장비나 보안 서비스의 입력 계약이 마련되면 별도 작업으로 설계한다.
