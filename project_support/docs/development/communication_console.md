# 통신 탭 사용 및 계산 규칙

지구 지도 오른쪽 아래에 대시보드 및 노드 지도와 같은 조준 버튼, 확대 및 축소 버튼, 세로 슬라이더를 제공한다. 조준 버튼은 선택 위성이나 지상국으로 이동하며, 선택 대상이 없으면 비활성화된다. 상단 해 음영 버튼은 세 지도의 표시 설정을 함께 바꾸고 브라우저에 저장한다. 연결도는 지리 지도가 아니므로 해당 모드에서는 지도 제어를 숨기고 해 음영 버튼을 비활성화한다.

통신 탭은 노드 탭에서 `배치 완료 → 대시보드`로 반영한 내 위성과 운용자가 둔 지상국으로 통신망을 구성해 보여 주는 화면이다. 위성의 위치, 위성 사이의 OISL 기하와 단말 상태, 지상국에서 본 고각과 거리 같은 상태는 디지털 트윈이 만든다. 어느 링크를 쓸 수 있는지, 어느 길로 데이터가 흐르는지, 지상 경로가 없을 때 데이터를 얼마나 보관하는지는 데이터 송수신 기술(데이터 패브릭) 모듈의 판정이며, 디지털 트윈은 그 판정을 ICD-02 메시지로 받아 표시만 한다. 두 역할을 섞지 않는다.

## 화면 사용

왼쪽 `네트워크 구성`은 위성, 지상국, 링크 목록이다. 위성 행의 점은 패브릭 판정에 따라 초록(지상 경로 있음), 주황(지상 경로 없음, 보관 중), 빨강(저장 용량 초과), 회색(패브릭 미응답)이다. `지상국` 목록에서는 프리셋(서울, 대전, 제주, 스발바르, 트롬쇠, 페어뱅크스, 이누빅, 싱가포르, 하와이, 아타카마, 푼타아레나스, 호바트) 또는 직접 입력으로 지상국을 추가하고, 행을 고르면 아래에 편집 폼(이름, 위도, 경도, 고도, 안테나 지름, 최소 고각, 대역, 사용 여부)이 열린다. 지상국 집합은 브라우저 localStorage에 저장되는 화면 구성이며 서버 상태가 아니다. `링크` 목록은 OISL, 지상 RF, 지상망 순서로 정렬되고 패브릭이 사용 가능으로 본 링크가 앞에 온다.

가운데는 같은 데이터를 두 가지로 본다. `지구 3D`는 위성과 지상국의 실제 위치, OISL 링크 선(초록 양방향, 주황 포착·구동), 지상 링크 선(하늘색 사용 가능, 회색 점선 가시하지만 사용 불가, 빨강 점선 장애), 계산 경로(보라색 굵은 선), 지상국 커버리지(배치 위성의 중간 고도에서 최소 고각을 넘는 지상 반경)를 그린다. 도구 모음의 `궤적`, `OISL`, `지상 링크`, `커버리지`, `3D 모델`은 각 표시를 끄고 켠다. `연결도`는 궤도면마다 위성을 원형으로 배치하고 지상국을 아래 지상 구역에 경도순으로 둔 논리 연결도다. 궤도면은 승교점 적경이 이웃한 면끼리 붙도록 격자를 지그재그로 채운다. 같은 궤도면 이웃 사이의 OISL 링크는 원을 따라 호를 그리고, 다른 궤도면 사이의 링크는 선택이나 경로와 관계없을 때 옅게 그려 궤도면 구조가 먼저 읽히게 한다. 지상 접속은 긴 선 대신 위성 카드 바깥쪽에 붙는 작은 표(지상국 이름과 품질, 장애면 `장애`)로 표시하며 한 위성에 여러 지상국이 닿으면 표를 바깥으로 쌓는다. 지상국까지 선을 그리는 것은 계산 경로에 포함된 접속과 선택한 접속뿐이다. 표를 누르면 그 링크가 선택되고 지상국을 고르면 그 지상국의 표만 진하게 남는다. 연결도의 링크 색은 패브릭 판정(초록 75 % 이상, 주황 그 아래, 하늘색 지상, 빨강 장애, 회색 점선 사용 불가)을 따르고, 선택 링크와 계산 경로에는 품질 표가 붙는다. 분석 시계는 대시보드와 노드 탭의 시계와 별개인 UTC 커서이며 정지, 60초 스텝, 배속, 현재 복귀를 제공한다. 탭을 처음 열면 OISL 포착 순서를 분석 시각 2분 전부터 두 단계로 진행시켜 편대가 정상 상태로 나타난다. 포착 순서는 분석 시각에 대해 결정론적이므로 이는 시작 시점을 앞당기는 것이지 상태를 지어내는 것이 아니다.

경로 막대에서 출발지와 목적지(위성 또는 지상국)와 목적(최저 지연, 최대 신뢰도, 균형)을 고르고 `경로 계산`을 누르면 패브릭이 마지막 네트워크 상태에서 경로를 찾는다. 경로는 이후 매초 다시 계산되어 위성이 움직여도 따라간다. 아래 `경로 결과`에 구간별 지연, 용량, 품질과 편도 지연 합계, 병목 용량, 경로 신뢰도(구간 품질의 곱)를 보인다. `지상국 접속창`은 고른 지상국에서 앞으로 3시간 안에 최소 고각 위로 올라오는 위성의 AOS, LOS, 최대 고각, 지속 시간이며 대시보드의 관측창 예측과 같은 계산이다. `저장 전달`은 패브릭이 보고한 위성별 보관 데이터량과 상태(실시간 전달, 보관분 전달 중, 보관 중, 저장 용량 초과)다.

오른쪽 `선택 항목`은 위성, 지상국, 링크에 따라 트윈이 계산한 기하와 패브릭 판정을 나눠 보인다. 위성은 현재 위치, 지상 경로와 다음 홉, 지상까지 지연, 저장 전달 상태, OISL 링크와 가시 지상국이다. 지상국은 시설 값, 커버리지 반경, 담당 위성 수, 지금 가시 위성이다. 링크는 트윈 기하(거리, OISL 기하 여유 또는 위성 EIRP와 지상국 G/T)와 패브릭 판정(편도 지연, 용량, 품질, Eb/N0 여유, BER), 품질 이력 그래프이며, 지상 RF 링크는 서버의 Friis 링크 버짓을 링크 값으로 미리 채워 계산할 수 있다. 맨 위 `데이터 패브릭` 표시는 연결 방식(내장 임시 구현 또는 외부 주소), 응답 시간, 메시지 순번을 보이고 응답이 없으면 빨간색으로 바뀐다. `⚡ 장애 주입`은 선택 항목을 대상으로 SIM 장애 대화상자를 연다. `링크 손실`은 그 위성이나 지상국이 닿는 모든 링크 또는 그 링크를 사용 불가로 만들고, `지연 증가`는 그 위성을 지나는 경로에 심각도별 지연(40, 85, 200 ms)을 더한다.

## 역할 분담과 ICD-02

| 역할 | 위치 | 내용 |
|---|---|---|
| 상태 생성 (디지털 트윈) | `digital_twin/simulation/browser/satellite_dynamics.js`, `oisl.js`, `ground_links.js` | 위성 위치, OISL 기하와 단말 포착 순서, 지상국 고각·방위·거리, 사용 가능한 RF 대역, 위성 EIRP와 지상국 G/T, 지상망 거리 |
| 메시지 구성 (디지털 트윈) | `digital_twin/simulation/browser/network_snapshot.js` | 위 상태와 활성 SIM 장애를 ICD-02 `네트워크 상태 갱신` 메시지로 묶는다 |
| 판정 (데이터 패브릭 임시 구현) | `operations_software/data_fabric/` | 링크별 사용 가능 여부, 지연, 용량, 품질, BER, 위성별 지상 경로와 다음 홉, 저장 전달 백로그, 요청 경로 |
| 연결 | `communication/http/data_fabric.py`, `communication/external/data_fabric.py`, `communication/browser/data_fabric.js` | 서버 ICD 끝점, 외부 모듈 전달, 브라우저 클라이언트 |
| 표시 | `digital_twin/visualization/network_scene.js`, `network_diagram.js`, `user_application/web/scripts/tabs/communication.js` | 지구 3D 계층, 연결도, 화면 조립 |

메시지 구조와 패브릭 임시 구현의 가정은 [운용 SW 임시 구현 README](../../../operations_software/README.md)에 있다. 패브릭이 응답하지 않으면 화면은 링크 판정, 경로, 저장 전달 값을 비워 두고 `미응답`을 표시한다. 브라우저가 만든 값으로 대신 채우지 않는다.

### 연결 방식

기본은 내장이다. 서버가 `DataFabricStandIn`을 프로세스 안에서 만들고 `/api/data-fabric/network`, `/route`, `/status`로 응답한다. `python main.py --data-fabric-url http://호스트:포트`로 실행하면 서버가 같은 ICD를 제공하는 외부 모듈로 요청을 전달하고, 응답이 없으면 503으로 보고한다. 브라우저 쪽에서는 설정 탭의 링크 L02(데이터 패브릭 ↔ 통합 프레임워크)에 원격 호스트와 포트를 지정하면 콘솔이 그 주소의 `/api/data-fabric/*`를 직접 호출한다. 호스트가 비어 있거나 로컬(`self`, `localhost`, `127.x`)이면 이 서버를 쓴다.

## 계산 모델

### 지상 링크 기하 (디지털 트윈)

`ground_links.js`는 대시보드와 같은 WGS84 관측 기하(`orbit.js`의 `lookAnglesAt`)로 지상국에서 본 위성의 고각, 방위각, 경사거리를 구한다. 위성의 RF 장비 중 켜져 있고 지상국이 지원하는 대역을 Ka, X, S 순으로 고른다. 안전 모드는 S 대역 TT&C만 남긴다. 위성 EIRP는 장비 소비 전력을 송신 전력으로 보고 대역별 대표 안테나 이득(S 3, X 15, Ka 20 dBi)을 더한 값이며, 지상국 G/T는 안테나 지름과 대역 주파수(S 2.2, X 8.2, Ka 20 GHz), 개구 효율 0.6, 대역별 시스템 잡음 온도(S 150, X 200, Ka 300 K)에서 계산한다. 지상국 사이의 지상망은 모든 지상국을 잇는 완전 연결로 두고 대원 거리를 쓴다. 이 값들은 대표 공학값이며 실제 시설의 제원이 아니다.

지상국 커버리지 반경은 구형 지구에서 고도 h의 위성이 최소 고각 m 위로 보이는 지상 범위 `acos(Re / (Re + h) · cos m) − m`에 적도 반지름을 곱한 값이다. 지형, 굴절, 안테나 지향 한계는 없다.

### 데이터 패브릭 판정 (임시 구현)

지연은 거리 / 광속(지상망은 0.67c)에 처리 지연(OISL 1.5 ms, 지상 4 ms, 지상망 3 ms)을 더한 편도 값이다. OISL 여유는 트윈이 보고한 정격 거리 기준 기하 여유이고, 지상 RF 여유는 EIRP + G/T − 자유공간 손실 − 구현 손실 6 dB − 대기 손실(대역별 천정값 / sin 고각) + 228.6 − 10 log10(전송률) − 9.6 dB(QPSK, BER 1e-5)다. 품질은 여유 −10 dB에서 0 %, 0 dB에서 50 %, +10 dB에서 100 %이고 용량은 3 dB 이상에서 정격, 0 dB에서 절반, 음수에서 0이다. OISL은 트윈이 `양방향 유지`로 보고한 링크만, 지상 링크는 최소 고각 위이고 여유가 0 dB 이상인 링크만 사용 가능이다. 경로는 사용 가능한 링크로 만든 무방향 그래프의 최단 경로이며 목적별 비용은 지연, −ln(품질/100), 또는 `지연 × 0.65 + (100 − 품질) × 1.1`이다. 위성별 지상 경로는 모든 지상국을 출발점으로 둔 한 번의 Dijkstra로 구한다.

저장 전달 백로그는 위성별 총량만 다룬다. 위성은 상시 0.2 Mbps에 켜진 임무 탑재체당 40 Mbps를 생성하고, 저장 용량은 켜진 저장 장치의 합(없으면 64 GB)이다. 지상 경로가 있으면 경로 병목 용량으로 내려보내고, 없으면 용량까지 보관하며 넘치면 폐기로 센다. 두 메시지 사이의 경과 시간은 트윈의 분석 시각 차이이므로 시계를 멈추면 백로그도 멈추고, 과거로 돌리면 백로그를 비운다. 개별 번들, 수명, 우선순위는 없다.

## 코드 확장 규칙

- 지상국 모델은 `model_library/browser/ground_stations.js`, 지상 링크 기하는 `simulation/browser/ground_links.js`, ICD 메시지 구성은 `simulation/browser/network_snapshot.js`에 둔다. DOM, API, 저장소를 호출하지 않는다.
- 패브릭 판정 로직은 `operations_software/data_fabric`에만 둔다. 브라우저나 트윈 코드에서 경로, 품질, 백로그를 다시 계산하지 않는다. 패브릭이 없으면 값이 없는 것이다.
- ICD-02 메시지 필드를 바꿀 때는 `communication/http/schemas.py`, `operations_software/README.md`, `network_snapshot.js`와 두 쪽의 시험을 함께 바꾼다.
- Cesium 표현은 `visualization/network_scene.js`(NodeScene 확장), 연결도는 `visualization/network_diagram.js`가 맡는다. 주입받은 globe와 시각 함수만 쓴다.
- 지상국 작업 세트는 `scripts/communication/ground_segment.js`, 화면 조립은 `scripts/tabs/communication.js`, 스타일은 `styles/communication.css`에 두고 `#view-communication` 범위로 제한한다.
- 실제 패브릭 모듈이 오면 `communication/external/data_fabric.py`의 주소 지정으로 연결하고 `operations_software/data_fabric`은 시험 참고용으로만 남긴다.
