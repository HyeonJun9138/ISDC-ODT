# 노드 탭 사용 및 계산 규칙

노드 탭은 사용자가 위성 노드를 임시로 두고 궤도, 3D 모델, 임무 장비와 편대 배치를 바꿔 보는 샌드박스다. 왼쪽은 내 위성만 보이는 궤도 뷰, 오른쪽은 선택 위성의 상태와 편집 폼, 아래는 편대 프리셋과 슬라이더다. 작업 세트는 브라우저의 localStorage에 저장되며 `배치 완료 → 대시보드`를 누르면 그 시점의 사본이 대시보드(궤도 탭)의 카탈로그에 합쳐진다. 서버 런타임과 SIM 텔레메트리는 이 탭의 영향을 받지 않는다.

## 화면 사용

지도 오른쪽 아래 조준 버튼으로 선택 위성의 뷰를 정렬하고, 그 아래 +/− 버튼과 세로 슬라이더로 확대 수준을 조절한다. 선택 위성이 없거나 위치를 사용할 수 없으면 조준 버튼은 비활성화된다. 색상과 확대 제어는 대시보드 및 통신 지도와 같은 구현을 사용한다. 상단 해 음영 설정도 세 지도에 함께 적용된다.

왼쪽 궤도 뷰는 대시보드와 같은 Cesium 지구를 쓰지만 GP 카탈로그 대신 작업 세트의 위성만 표시한다. 모든 위성에 지정한 3D 모델을 실제 축척으로 두고, 각 위성의 궤적을 옅게 그리며, OISL 단말이 상대를 잡으면 두 위성 사이에 링크 선을 그린다. 선택 위성은 대시보드와 같은 방식으로 클릭 시 화면 중앙에 오고, `뷰 정렬` 또는 두 번 클릭으로 근접 추적한다. 도구 모음의 `궤적`, `OISL 링크`, `3D 모델`은 각 표시를 끄고 켠다. 오른쪽의 `☀` 버튼은 해 방향에 따른 음영을 끄고 켜며, 끄면 지구 전체가 해가 비추는 쪽과 같은 밝기로 고르게 보인다. 이 선택은 대시보드 및 통신 지도와 공유되고 브라우저에 저장된다. 분석 시계는 대시보드의 분석 시계와 별개인 UTC 커서이며 정지, 60초 스텝, 배속, 현재 복귀를 제공한다. 배속을 올리면 짐벌 구동과 포착 순서가 그 시간 비율로 진행된다.

오른쪽 위 `내 위성` 목록의 점은 링크 상태다. 초록은 양방향 링크를 유지하는 위성, 주황은 포착 중이거나 단방향, 빨강은 모든 상대가 차단된 위성, 회색은 상대가 없는 위성이다. 위성을 고르면 아래에 버스, 운용 모드, 편대 소속, 3D 모델, 정의 궤도요소와 현재 위치, 순간 전력 수지, 장비 사용 현황과 OISL 단말별 상태가 표시된다. `편집`을 누르면 같은 자리에 편집 폼이 열린다.

편집 폼은 다섯 부분이다. 기본 정보(이름, 버스 프리셋, 운용 모드), 3D 모델(매니페스트의 모든 모델과 미리보기), 임무 장비(장비 추가와 제거, 사용 여부, OISL 단말의 장착 방향과 상대 위성), 궤도(평균 고도, 이심률, 경사각, 승교점 적경, 근지점 편각, 평균 근점 이각, 정의 시각), 전력과 질량(발전 전력, 버스 소비, 배터리 용량, 건조 질량)이다. 버스 프리셋을 바꾸면 모델, 전력, 질량과 장비가 프리셋 값으로 다시 채워진다. 저장하면 정의를 검증하고 통과한 경우에만 작업 세트를 바꾼다. 편대에 속한 위성을 저장하면 편대에서 분리되어 이후 슬라이더의 영향을 받지 않는다.

아래 `편대 배치`는 단일, 열차형, Walker Δ, Walker ★ 프리셋과 슬라이더(궤도면 수, 면당 위성 수, 고도, 경사각, 위상 계수, 위성 간 간격, 첫 궤도면 승교점 적경, 궤도면 분포 폭, 첫 위성 평균 근점 이각)로 여러 위성을 한 번에 만든다. 이름 접두사, 버스 프리셋, OISL 링크 정책(앞·뒤·좌·우 4링크, 앞·뒤만, 사용 안 함)도 여기서 정한다. 슬라이더 아홉 개는 프리셋과 관계없이 항상 같은 자리에 있고, 현재 프리셋이 쓰지 않는 항목은 흐리게 비활성화되어 패널 높이가 바뀌지 않는다. 각 프리셋 버튼, 슬라이더, 선택 상자, 버튼에 마우스를 올리거나 초점을 두면 작은 안내가 뜨며, `편대 생성` 버튼의 안내에는 현재 설정으로 만들어질 위성 수, 면 간 승교점 간격, 위성 간 위상과 직선 거리, 궤도군과 주기가 표시된다. `편대 생성`은 새 편대를 작업 세트에 추가하고, `슬라이더 즉시 반영`이 켜져 있으면 이후 슬라이더 조작이 같은 편대를 그 자리에서 다시 배치한다. 목록에서 편대 소속 위성을 고르면 그 편대의 값이 슬라이더에 실린다. `편대 제거`는 현재 편대의 위성만, `전체 비우기`는 작업 세트 전체를 지운다.

`배치 완료 → 대시보드`는 작업 세트의 사본을 배치 기록으로 저장하고 대시보드 카탈로그에 즉시 합친다. 하단 문구는 반영된 위성 수, 반영 시각과 미반영 변경 여부를 보여준다. `회수`는 대시보드에서 내 위성을 모두 뺀다. 대시보드에서 내 위성은 목록과 지구에 GP 객체와 함께 나타나고, 선택하면 분석 패널이 `내 위성 / Kepler + J2`로 표시되며 SATCAT을 조회하지 않는다. 대시보드 카탈로그의 궤도 구분 버튼 중 `SDC`(Space Data Center)는 배치한 내 위성만 목록과 지구에 남기는 필터이며, 검색어와 관심 필터, 정렬은 그대로 적용된다. 참조 번호는 900001부터 순서대로 부여하는 내부 번호이며 NORAD 번호가 아니다.

## 계산 모델

### 궤도 다이나믹스

`digital_twin/simulation/browser/satellite_dynamics.js`는 정의 시각의 Kepler 요소(장반경은 평균 고도에 적도 반지름 6378.137 km를 더한 값, 이심률, 경사각, 승교점 적경, 근지점 편각, 평균 근점 이각)에 J2 영년 섭동을 적용한다. 승교점 적경, 근지점 편각, 평균 근점 이각의 변화율은 Vallado의 영년 항을 쓰며 `J2 = 1.08262668e-3`, `mu = 398600.4418 km^3/s^2`다. Kepler 방정식은 Newton 반복으로 푼다. 관성 좌표계는 세차와 장동이 없는 평균 적도 좌표계이고, 지구 고정 좌표계로의 변환은 IAU-82 그리니치 평균 항성시만 쓴다(UT1을 UTC로 간주, 극운동 없음). 표시 위치는 WGS84 위도, 경도, 타원체 고도이며 속력은 관성계 속도벡터의 크기다.

허용 범위는 근지점 고도 120 km 이상, 원지점 고도 200,000 km 이하, 이심률 0 이상 0.95 미만, 경사각 0~180°다. 범위 밖 정의는 위치를 제공하지 않으며 기본값으로 대체하지 않는다. 대기 저항, 제3체 중력, 태양 복사압, 기동, 고차 조화항은 모델에 없다. 이 계산은 GP/SGP4가 아니고 관측 자료에 맞춘 궤도가 아니며 실측 텔레메트리도 아니다.

태양 방향은 Vallado 알고리즘 29의 저정밀 태양 위치를 쓰고, 일조 여부는 지구 반지름의 원통 그림자로 판정한다. 반영 및 대기 굴절은 고려하지 않는다. 배터리 충전 상태는 시간 적분하지 않으며 전력 수지는 순간값(일조 시 발전 전력에서 버스와 사용 중 장비의 소비를 뺀 값)이다.

### OISL 단말

`digital_twin/simulation/browser/oisl.js`는 광 위성 간 링크 단말을 기하학적으로 모델링한다. 지향은 소유 위성의 LVLH 좌표계(x는 속도 방향, z는 천정, y는 진행 방향 기준 왼쪽)에서 방위각과 고각으로 나타낸다. 앞 방향이 방위각 0°, 왼쪽이 +90°, 뒤가 180°, 오른쪽이 −90°다. 단말은 장착 방향(앞, 뒤, 왼쪽, 오른쪽, 자동)에 따른 조준 방위각을 중심으로 방위 반각과 고각 범위의 가동 범위를 갖는다.

링크 가능 조건은 순서대로 판정한다. 두 위성을 잇는 선분이 지구 반지름에 100 km 대기 여유를 더한 구를 지나면 `지구 가림`, 거리가 단말의 정격 거리 밖이면 `거리 초과`, 짐벌 가동 범위 밖이면 `가동 범위 밖`이다. 여유도는 정격 거리 대비 자유공간 기하 손실 `20 log10(정격 거리 / 현재 거리)` dB이며 표시용 품질은 0 dB에서 50 %, 10 dB에서 100 %다. 이는 링크 예산이 아니다.

포착 순서는 분석 시각에 대해 결정론적이다. 상대가 정해지면 짐벌이 최대 각속도로 목표 방위와 고각을 향해 구동(`짐벌 구동`)하고, 도달 후 포착 시간 동안 `포착 중`을 거쳐 `추적`이 된다. 가시선이 끊기면 `가시선 차단`이 되고 회복하면 포착부터 다시 시작한다. 상대를 바꾸면 순서가 처음부터 진행된다. 분석 시각을 과거로 되돌리면 역방향 이력이 없으므로 그 시각에서 새로 시작한다. 지향 오차는 구동 중 남은 각도, 포착 중 지터의 3배, 추적 중 지터다.

자동 상대 선택은 장착 방향의 45° 구간 안에서 링크 가능한 가장 가까운 위성을 고르되, 편대에 속한 위성의 앞·뒤 단말은 같은 궤도면의 위성만, 왼쪽·오른쪽 단말은 다른 궤도면의 위성만 먼저 고려한다(그 궤도면에 후보가 없을 때만 구간 안의 아무 위성). 촘촘한 격자에서는 인접 면의 위성이 거의 정면에 더 가까이 놓여 앞 단말을 차지하고 같은 면의 고리를 끊기 때문이다. 이미 잡은 상대는 그 우선 조건을 만족하는 한 유지해 인접 위성 사이에서 링크가 흔들리지 않게 한다. 같은 위성의 다른 단말이 잡은 상대는 제외한다. 상대를 직접 지정한 단말은 차단 중에도 그 상대를 유지한다. 두 위성 사이의 링크는 양쪽 단말의 상태를 합쳐 `양방향 유지`, `단방향`, `포착 중`, `짐벌 구동`, `가시선 차단`으로 표시한다.

### 모델 라이브러리

`digital_twin/model_library/browser/satellite_nodes.js`는 버스 프리셋(평판형 통신위성, 소형 통신위성, 지구관측 소형위성, 3U 큐브샛, 정지궤도 중계위성), 장비 카탈로그(OISL 표준·장거리·소형 단말, Ka·X·S 대역 RF 링크, 광학 카메라, DTN 저장 장치, GNSS 수신기), 운용 모드(정상, 대기, 안전), 편대 프리셋과 생성기를 정의한다. 값은 공개 자료를 어림한 대표 공학값이며 제조사 제원이 아니다. 안전 모드는 TT&C와 항법 수신기만 켜고, 대기 모드는 OISL 단말을 끈다.

Walker 배치는 궤도면을 분포 폭에 고르게 나누고, 면 안에서는 360°를 면당 위성 수로 나누며, 면 사이 위상차는 `F × 360° / 전체 위성 수`다. 열차형은 한 궤도면에서 지정한 위상 간격으로 위성을 잇달아 둔다. 편대 요약의 직선 거리는 같은 궤도면 이웃 사이의 현 길이다. 550 km 고도에서 표준 단말의 정격 거리 5,000 km와 지구 가림 조건을 동시에 만족하려면 같은 면의 이웃이 약 41° 이내여야 하므로 기본값은 면당 10기다.

## 코드 확장 규칙

- 노드 궤도와 태양 조건은 `simulation/browser/satellite_dynamics.js`, OISL 단말은 `simulation/browser/oisl.js`에 둔다. DOM, API, 저장소를 호출하지 않는다.
- 카탈로그 위치 함수 `positionAt`은 `dynamics === 'kepler_j2'`인 항목만 노드 계산으로 보내고 나머지는 기존 GP와 DEMO 규칙을 유지한다.
- 모델 정의(버스, 장비, 편대)는 `model_library/browser/satellite_nodes.js`에 둔다. 새 장비는 `kind`, 소비 전력, 질량을 갖고, OISL 단말은 정격 거리, 가동 범위, 각속도, 포착 시간, 지터를 갖는다.
- 다중 모델, 궤적, 링크 선의 Cesium 표현은 `visualization/node_scene.js`가 맡는다. 주입받은 globe와 시각 함수만 사용하며 화면 상태나 API를 import하지 않는다.
- 작업 세트와 배치 기록은 `scripts/nodes/constellation.js`, 링크 결정은 `scripts/nodes/links.js`, 편집 폼은 `scripts/nodes/editor.js`, 화면 조립은 `scripts/tabs/nodes.js`에 둔다. 스타일은 `styles/nodes.css`에 한정하고 `#view-nodes` 범위로 제한한다.
- 새 수치는 근거, 단위, 좌표계, 시간 기준과 결측 정책을 먼저 정의한다. 범위 밖 정의를 정상값으로 보완하지 않는다.
